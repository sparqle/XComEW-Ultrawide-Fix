# XCOM: Enemy Within ultrawide fix

Build on Windows with Python 3.10 or newer. One-time setup in your selected Python environment: `python -m pip install -r requirements-build.txt` (or `uv pip install --python .venv/Scripts/python.exe -r requirements-build.txt` for a uv-managed environment).

In PyCharm, select the project's Python interpreter, then run the shared **Build executable** configuration, or right-click `build.py` and choose **Run**. From the command line, run `python build.py` with that same environment activated, or use `build-windows.bat` (active environment first, then the project's `.venv`, then `py -3`). PyCharm's ordinary Build Project action does not package Python applications; this run configuration performs that step.

Both routes produce `dist\XComEW-Ultrawide-Fix.exe`, a Windows GUI with the EXE patcher embedded. The build copies `mods/Fix-ultrawide-HPBars.txt` to `dist/mods`; patch scripts are read from `mods` beside the application, never embedded. Rebuilding preserves generated uninstall files. Python is only required to build it. Build paths are resolved relative to `build.py`, so the working directory does not matter. To run the GUI from source, run `src/app.py`.

For the HP bar patch, supply Windows `DecompressLZO.exe` and `PatchUPK.exe` from [UPKUtils](https://github.com/wghost/UPKUtils). Put both in the project's `binaries` folder. After packaging, the build copies that folder's contents to `dist/binaries`, updating existing files. If the source folder is absent, the build skips this step. These tools remain separate from `XComEW-Ultrawide-Fix.exe`; distribute the `binaries` folder alongside it. PatcherGUI.exe is unnecessary. If you check the skip HP bar option, neither tool is needed and only `XComEW.exe` is modified or restored.

Select the `XCom-Enemy-Unknown` directory, leave the skip HP bar option unchecked to install or restore both, and click Install or Restore. The app derives `XEW\Binaries\Win32\XComEW.exe` and `XEW\XComGame\CookedPCConsole\XComGame.upk`. It stages UPK operations outside the game directory; if DecompressLZO reports the UPK is already decompressed, it stages a copy. It records hashes in `XEW\Binaries\Win32\.ultrawide-fix.json` and keeps an EXE backup beside the executable. No permanent UPK backup is created. Keep the EXE backup, state file, and application mods directory until restored. Installing a decompressed UPK removes its `.uncompressed_size` sidecar; a failed commit restores the previous UPK and sidecar. Successful uninstall leaves the UPK decompressed, without that sidecar. Close the game first.

The UI delegates EXE installation, restore, and status to the supplied Python patcher. Click Status to inspect the EXE and, unless skipped, the managed HP-bar installation. Patcher output and errors appear in the UI log. The EXE must have all three original byte sequences or already have the complete patch installed; other builds and partial patches are rejected. An already-patched EXE is left unchanged. Restore copies the verified EXE backup and applies the installation-specific uninstall script generated by PatchUPK. This script is saved under a unique name in `mods` beside the application, with its relative path and hash recorded in the game state. Missing or changed uninstall scripts are rejected. Older installations without a recorded generated script require their original tool or backup for restoration. Restore only manages patches installed through this app; externally installed patches must be restored with their original tool. If PatchUPK fails, the game UPK stays untouched. Restoring via the uninstall script restores its game data, not necessarily its original compressed bytes.
